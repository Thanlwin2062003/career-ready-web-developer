🔨 CSS Specificity: The Chain of Command

Open your browser's DevTools and inspect each element to see which rules are applied and which are crossed out.

1. Same Specificity — Last Rule Wins

This title should be GREEN.

Two identical .demo1-title selectors. The second one sets color: green and comes last, so it wins.

2. Two Classes on One Tag — Property-by-Property

This has a GOLD border and NAVY text.

.demo2-border gives border: gold and color: crimson.
.demo2-text overrides only color to navy.
The border from .demo2-border survives because there's no conflict.

3. Chained Classes (.class1.class2) — More Specific

This should be ORANGE and BOLD.

.demo3-box.chained (two classes, specificity 20) beats .demo3-box (one class, specificity 10).

4. Class Selector vs Tag Selector

This should be FUCHSIA, not lime.

The h4 tag selector comes LAST in the CSS, but the CLASS .demo4-override has higher specificity (10 vs 1).

5. Tag + Class vs Two Chained Classes

This should be TOMATO, not dodgerblue.

h5.demo5-mixed = specificity 11 (tag 1 + class 10).
.demo5-mixed.chained-demo5 = specificity 20 (two classes).
The chained classes win.

6. ID Selector — The Wrecking Ball

This should be RED, despite three classes.

#demo6-id = specificity 100.
h6.demo6-class.chained-again.more-chains = specificity 31.
The ID wins. Always.

7. !important — Breaking the Cascade

GREEN text, RED border.

#demo7-id wants color: red and border: red.
.demo7-class uses color: green !important, so it steals the color.
But the border from the ID still applies because .demo7-class doesn't use !important on its border.
This is why !important is a nightmare.

💡 Pro tip: Stick to classes. Avoid IDs for styling. Never use !important unless you're debugging or overriding third-party code you can't control.
